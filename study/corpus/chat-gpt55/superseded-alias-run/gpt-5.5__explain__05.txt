Encryption and hashing are both ways to transform data, but they serve different purposes.

## Encryption

**Encryption is reversible.** It converts readable data, called plaintext, into unreadable data, called ciphertext, using a key. Someone with the correct key can decrypt it back to the original data.

Example:

```text
Message: "Hello"
Encrypted: "X9a$2..."
Decrypted with key: "Hello"
```

Encryption is used when you need to protect data but later recover it.

Common uses:

- Secure messaging
- HTTPS/TLS
- Encrypting files or disks
- Protecting stored sensitive data

Key point:

> Encryption protects confidentiality and is meant to be decrypted by authorized parties.

## Hashing

**Hashing is one-way.** It converts data into a fixed-size value called a hash or digest. You cannot practically reverse a hash to get the original input.

Example:

```text
Input: "Hello"
Hash: "185f8db32271fe25f561a6fc938b2e264306ec304eda518007d1764826381969"
```

Hashing is used when you want to verify data, not recover it.

Common uses:

- Password storage
- File integrity checks
- Digital signatures
- Detecting data changes

Key point:

> Hashing verifies that data matches or has not changed, but it does not allow recovery of the original data.

## Main differences

| Feature | Encryption | Hashing |
|---|---|---|
| Reversible? | Yes, with a key | No |
| Uses a key? | Usually yes | Usually no |
| Output | Ciphertext | Hash/digest |
| Purpose | Keep data secret | Verify data integrity or identity |
| Example use | Encrypting a message | Storing a password hash |

## Password example

Passwords should usually be **hashed**, not encrypted.

When you create an account, the system stores a hash of your password. Later, when you log in, it hashes the password you entered and compares it to the stored hash.

Good password hashing also uses:

- A **salt**, to prevent identical passwords from having identical hashes
- A slow hashing algorithm like **bcrypt**, **scrypt**, or **Argon2**

In short:

> Use encryption when you need to get the original data back.  
> Use hashing when you only need to verify that data is the same.
